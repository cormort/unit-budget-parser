# 單位預算「歲出計畫提要及分支計畫概況表」解析工具

把政府**單位預算案** PDF 裡的「歲出計畫提要及分支計畫概況表」轉成可篩選、可匯出的結構化表格。

單一 HTML 檔、純前端（pdf.js 讀檔、SheetJS 匯出），**檔案不上傳**。

---

## 一、要解決的問題

單位預算案是數百頁 PDF，其中「歲出計畫提要及分支計畫概況表」每頁**左半是結構表**（分支計畫／用途別科目對金額），**右半是自然語言的編列說明**。兩者在版面上並列，但沒有欄位對應關係。

要做分析，得先把左表拆成階層化的列，還要知道右邊那段敘述在講哪個科目——後者 PDF 沒有任何標記。

實測三個機關：行政院主計總處、教育部、農業部（115 年度）。

---

## 二、做法

### 結構表（左半）
靠**字元 x 座標**切欄（代碼與名稱 <160、金額 200–292、說明 ≥359），列則依 y 座標鄰近分群。階層純靠**代碼長度**判定：

| 層級 | 代碼 | 例 |
|---|---|---|
| 工作計畫 | 10 碼 | `3203100100 一般行政` |
| 分支計畫 | 2 碼 | `01 人員維持` |
| 用途別一級 | 4 碼、結尾 000 | `1000 人事費` |
| 用途別二級 | 其餘 4 碼 | `1040 加班費` |

科目名稱以**官方「歲出用途別科目分類定義」**（一級＋二級共 79 筆）依代碼校正，避免欄寬截斷或異體字。

### 編列說明歸戶（右半）
把該分支的敘述切句後，依可靠度**由高到低**逐段對應，每段只處理前一段的殘餘：

| 順位 | 規則 | 性質 | 標示 |
|---|---|---|---|
| 1 | 句中金額 == 科目金額，且全分支唯一 | 事實 | 白底 |
| 2 | 句中連續金額**加總** == 科目金額 | 事實 | 白底 |
| 3 | **多句**連續加總 == 科目金額（索引相鄰、解唯一） | 事實 | 白底 |
| 4 | 別名歸戶（敘述用字 ≠ 官方三級科目名） | 推論 | 白底 |
| 5 | 順序界限：前後科目都對到，中間 1:1 補上 | 推論 | 黃底 |
| 6 | `(n)` 子項繼承父句科目（限父句由二級認領） | 結構 | 白底 |
| 7 | 人數歸戶：待遇類科目按人員類型對應 | 推論 | 黃底 |
| — | 區間內多科目、句數對不上 | 不確定 | 橘底＋候選文字 |
| — | 以上皆不成立 | 留白 | — |

**規則 2、3 是關鍵**：科目金額常被拆成多筆明細，句中沒有整數。
- 規則 2（單句）：`加班費 66,589` ← 「員工超時工作加班費 **40,613** 千元，不休假加班費 **25,976** 千元」
- 規則 3（多句）：`對特種基金之補助 37,540,305` ← 三句 18,397,693＋3,960,858＋15,181,754（375 億）

多位數精確相等不可能是巧合，故列為事實級；但要求**索引相鄰且解唯一**，避免任意組合湊數。

**規則 7（人數歸戶）**：待遇類科目在敘述中多半只寫人數不寫金額，金額規則全部對不到。改抽出「〈人員類型〉N人」配對，依**官方科目定義**歸戶（1015 定義含警察人員→駐警歸此；1020 為依聘用條例／約僱辦法者；1025 為技工工友，駕駛屬技工）。
「職員N人」為彙總數且該分支有 1010 政務人員待遇卻未單獨列人數時，加註「（含政務人員）」，並在 1010 標示「含於『職員494人』內」。

### 驗算
內建**上下合計驗算**：二級→一級→分支→工作計畫預算金額，逐層核對。三份實測皆 **0 不符**。

---

## 三、功能

- 五個下拉篩選（工作計畫／分支計畫／一級科目／二級科目／**業務別註記＆承辦單位**）＋**編列說明全文搜尋**
- 查詢結果**合計列**固定在第一列（以二級葉節點加總，不重複計算上下層）
- 匯出 **xlsx / csv / json**（皆匯出目前查詢結果）
- **機關規則**下拉：通用（自動偵測機關名）／主計總處／教育部／農業部
- 「(n) 子項併回父句」選項（**預設關閉**，見下）

### 閱讀輔助
- **分支列不重印全文**：已歸戶的句子在各科目列已顯示；分支列只留「無金額總述句」＋「未歸戶句（摺疊，顯示句數）」。實測字數 主計總處 −85%、農業部 −63%。
- **逐句項目符號**，不連成一片段落。
- **本列金額高亮**：橘底多半是該金額在段落中出現不只一次，高亮後可一眼看到候選位置。

### 欄位
工作計畫編號｜工作計畫｜分支計畫編號｜分支計畫｜用途別科目代碼｜用途別科目｜金額｜編列說明｜業務別註記／承辦單位

最後一欄把緊接金額的括號註記抽出（承辦單位如「政風處」、法定業務別如「含媒體政策及業務宣導費600千元」），讓說明變短，並可當**查詢維度**：註記含金額逐筆皆不同，先歸類再篩，配合合計列可直接回答「本機關資通安全經費共編列多少」（實測 主計總處 16 列 152,640 千元、教育部媒體政策及業務宣導費 27 列 211,168 千元）。

## 五、已知限制（誠實揭露）

**教育部約 464 句敘述無法歸戶，這是資料本身的限制，不是規則能解。** 診斷顯示其孤兒句 **574/575 的金額不等於任何科目金額**——因為敘述按**單位／業務**切，而非按科目：

> 「3.辦理廉政教育、社會參與及研習活動…等經費 **1,757** 千元（政風處）。」

1,757 是政風處的跨科目經費，會分散進一般事務費、旅費、物品…屬**多對多**關係。任何硬歸戶都是臆測，因此**留白**並摺疊標示待複核。

**「(n) 子項併回父句」預設關閉**：`(1)(2)(3)` 的語意在機關間相反——主計總處的 `(n)` 是不同的二級科目，教育部的是同科目的三級明細。實測**在斷句階段合併**會降低精準度（農業部 二級有說明 221→208；主計總處說明由精準句變成整包），故僅保留為選項。
（規則 6 的 `(n)` 繼承不同：它在**比對完成後**才繼承歸屬，不改斷句、不影響任何科目的比對結果，且限父句由二級認領。）

**不拆三級科目**：概況表結構只到二級（官方定義：「在單位預算則為第二級科目」）。三級只存在於敘述文字中。量化後發現只有約一成多的二級能安全拆出三級，且多數掛不上官方三級碼（用字差異），投報比過低，故不做。

### 為什麼在此停手

最後一輪把 650 句孤兒全部重抽分類、逐一診斷，只找到兩條仍站得住腳的規則（多句加總、`(n)` 繼承），實作後孤兒句降至 503。其餘 92% 集中在教育部，成因是資料本身的多對多結構。

再往下加規則，只能多救個位數筆卻開始引入「看起來合理的錯答案」——因此停手，交由人工複核。這是原則 6 的實際應用。

## 六、貫穿的原則

1. **寧可空白＋標記，不要臆測**：不確定就留白或標色待複核。
2. **先量化再改規則**：動程式前先跑真實資料，算出會救到幾筆、誤傷幾筆。多次因此推翻原本的假設（如 `(n)` 合併、三級拆解）。
3. **規則鏈由精到鬆**：風險高的規則放最後，只處理殘餘。
4. **界限優於猜測**：結構約束能排除錯誤答案，排除不掉的就承認不知道。
5. **在上游修，不在下游補**：清理階段解決，勝過逐條放寬比對規則。
6. **知道何時停**：規則加到只能多救幾筆卻開始引入錯誤時就停手。

## 七、使用

開啟 `index.html`（或線上版）→ 選擇單位預算案 PDF → 解析。不需安裝、不需後端、檔案留在本機。

### 內建範例
沒有檔案也可直接試用，工具內建三份 115 年度單位預算案（皆為政府公開資訊）：

| 按鈕 | 檔案 | 特性 |
|---|---|---|
| 行政院主計總處 115年度 | `examples/dgbas-115.pdf` | 單一份、無附錄重印；歸戶率最高 |
| 教育部 115年度 | `examples/moe-115.pdf` | 有附錄重印；敘述按單位／業務切，多數無法歸戶 |
| 農業部 115年度 | `examples/moa-115.pdf` | 有附錄重印；多為委辦／捐助型敘述 |

三份都會通過上下合計驗算（0 不符），可直接比較不同機關的敘述風格差異。

## 八、與 budget-pdf-parser 的解析方式差異

本工具由 [budget-pdf-parser](https://github.com/cormort/budget-pdf-parser) 分出。兩者都在解析預算書的「編列說明」自然語言，但**架構完全不同**，原因是資料形態不同。

### 根本差異：階層從哪裡來

| | budget-pdf-parser（編列說明） | unit-budget-parser（本工具） |
|---|---|---|
| **文字來源** | 整頁文字，說明是**唯一**資料 | 說明只是表格的**一欄**（x≥359），逐列讀、按分支累積 |
| **階層來源** | 只能**從文字推**（中文標號＋官方科目表比對） | **左側結構表直接給**，是事實 |
| **比對鍵** | 科目**名稱**（名稱多變 → 需 6 層由精到鬆的回退鏈） | 科目**金額**（可精確驗證；名稱是輔助） |
| **驗證基準** | 跨章節對帳（拿同份 PDF 的另一節當基準） | 表格自身上下合計驗算（自帶基準） |
| **失敗表現** | 科目**分類錯**（黃底標示推論） | **找不到對應句**（留白／摺疊待複核） |

一句話：budget-pdf-parser 是「**沒有結構，要從文字造出結構**」；本工具是「**結構已知，要把文字掛回結構**」。
前者的難點在**分類**，所以規則鏈由精到鬆、大量標記推論；後者的難點在**歸屬**，所以規則以金額為主、可明確區分事實級與推論級。

### 清理與斷句流程

**budget-pdf-parser**：去頁碼／年度行 → 動態偵測頁首（重複出現 ≥3 次的短純中文行＝機關／基金名）→ 整段拼成一行 → 依 `壹、`／`一、`／`科目名－`／`1.` 標號與句末「。」重新斷行 → `(n)` 前換行縮排 → 清行內空白但**保留行首縮排**（縮排是階層線索）。

**unit-budget-parser**：移除機關名（自標題前自動偵測）與頁首字串 → 依「。」斷句 → 在「：」後的 `N.` 前補切 → `<n>` 子項併回父句。

### 最關鍵的技術差異：頁首出現的「位置」

- budget-pdf-parser 的頁首是**獨立的行**，整行刪除即可。
- 本工具的說明是**欄**，跨頁接續時頁首會被串進句子**中間**，甚至插在數字中間：

```
…所需經費12【單位：新臺幣千元預算金額1,620,528說明】,000千元
```

**原因**：說明欄的 x 範圍（≥359）同時涵蓋頁面右上的頁首元素，實測落在此範圍者恰有四個：

| x | 內容 |
|---|---|
| 488 | 單位：新臺幣千元 |
| 426 / 523 | 預算金額 / 其數值 |
| 375 | 說明（欄頭本身） |

它們位於頁面上方，逐列由上而下串接時排在該頁最前面，因此落在**跨頁交界**處；若前一頁的敘述剛好斷在數字中間（`12` ｜ `,000千元`），頁首就插進數字裡。

**正確解法是位置過濾，不是字串刪除**：以「表頭列的 y」為界，只取其下方的敘述（無表格的計畫內容／預期成果頁則以「工作計畫名稱及編號」列為界）。實測三份：頁首元素在表頭列以下出現 **0 次**，斷裂數字 **0 處**。

**為什麼不能用字串刪除**（這是本專案踩過的坑）：機關名與「說明」二字**也會正當出現在正文**——

```
因應氣候變遷…之【農業部】門科學技術    ← 農業部門（產業部門），刪後成「之門科學技術」
審查地方政府【農業部】門之年度施政計畫  ← 地方政府農業部門，刪後成「地方政府門之」
美國【農業部】農業研究署               ← USDA，刪後成「美國農業研究署」
依「【教育部】補助大專校院…」          ← 法規名稱被破壞
```

實測機關名 13 次、「說明」9 次皆屬正文。曾一度誤把這些當「頁首滲漏」而以字串刪除「修正」，實為破壞內容——**機關名在 x=281，根本進不了說明欄，從來就沒有滲漏**。現僅保留兩個實測正文出現 0 次的安全網字串（`單位：新臺幣千元`、`預算金額N`）。

**順序也很關鍵**：必須**先清理、再斷句**。反過來會產生 `,000千元` 這種斷裂數字而永遠比對不到（外部驗證用的獨立實作正是栽在這裡，導致孤兒句統計失真）。
